## SSH 隧道


可经任意已保存的服务器建立本地转发、远程转发或 SOCKS5 代理。每条隧道都显示实时连接数；SSH 连接断开时监听端口会被撤除，而不会留在那里接受注定走不通的流量。

## VPN 与反向代理隧道


OpsMaxx 支持 **WireGuard**、**OpenVPN** 与 **frp**。完整指南：**[docs/VPN.md](VPN.md)**。

真正的特点是它的默认形态：**WireGuard 完全运行在用户态，不需要管理员权限。** 它不创建网络接口，你的路由表与 DNS 都不受影响，即便 OpsMaxx 被强杀也没有任何东西需要清理。隧道体现为本地监听 —— `127.0.0.1` 上的一个 SOCKS5 代理，以及你定义的任何转发 —— 你再让具体的连接指向它。

这个取舍是刻意的。要访问一台跳板机、一个数据库或一个内部服务，并不需要把整台机器接入远端网络。当确实需要时，Linux 与 Windows 上只需切换一个开关（每次连接都会请求提权），并且有三条明确的限制：拒绝整机隧道（`0.0.0.0/0`）；若某前缀已被另一个接口路由，则拒绝而不是去争抢；macOS 由于缺少 Apple Developer ID 而被排除。[docs/VPN.md](VPN.md) 对这三条都有说明。它们都不影响默认形态。

- **看握手时长，而不只看一个绿点。** 进程还活着、但握手已经过期的 WireGuard 隧道会显示为琥珀色的 **degraded**，而不是绿色的已连接。「起来了但流量不通」和「已经断了」是两种不同的问题，而几乎没有客户端会区分它们。
- **VPN 之上的 SSH 与数据库。** 给某台服务器或某个数据库选中一个配置，它会随会话一起启动、等待就绪、并随会话一起拆除。如果它起不来，你看到的是**这个 VPN 自己的**报错，而不是二十秒后才出现的连接超时。
- **导入的配置被视为不受信任。** 一个 `.ovpn` 文件可以执行程序 —— `up`、`plugin`、`script-security` 之类会在连接服务器之前就运行。OpsMaxx 从不把你的文件交给 OpenVPN：它先解析，拒绝任何会执行程序的内容（并把那一行原样引给你看），再用剩下的部分重新生成一份配置。WireGuard `.conf` 里的 `PostUp`/`PostDown` 同样会被拒绝。
- **默认不分流全局流量。** 即便配置里要求，`redirect-gateway` 也不会自动开启。下载一个配置不应该悄悄改变整台机器的路由。
- **frp 会用它的话说清暴露了什么。** 每个代理都带一句确认：*「让 127.0.0.1:5432 可从 frp.example.com 访问。」* 每一句都勾选之后，该配置才会启动。
- **没有任何访问组允许 AI 代理启动 frp 配置** —— 只有你亲自设为 Bypass 配置的会话可以 —— 而启动任何 VPN 在 Auto 与 Ask first 配置下都需要审批，在自定义访问组下也是如此，除非它的「有风险操作需确认」开关已关闭（Full Access 出厂即为关闭）。见 [AI-MCP.md](AI-MCP.md#permission-profiles)。

**每个隧道引擎都随应用打包，其中有一个不是开源的。** WireGuard（经由 MIT 许可的 `wireguard-go`）、frp（Apache-2.0）与 OpenVPN（GPL-2.0，macOS 与 Linux）都在发版时从钉住的上游源码构建 —— 无需另外安装，且每个二进制在执行前都会校验哈希。Windows 上的 OpenVPN 需要一个无法作为文件分发的适配器驱动，因此在 Windows 上使用 OpenVPN 配置时，仍然会用你自己安装的 OpenVPN。Windows 还会附带 `wintun.dll`，它是**专有软件** —— OpsMaxx 中唯一一个非开源组件，且只有 WireGuard 的系统模式需要它。打包 GPL 软件使本项目有义务发布对应源码，因此每个发版都会把 OpenVPN 的源码作为附件一并发布。所有这些都写在 [THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md) 里。

**没有 kill switch。** 隧道断开时 OpsMaxx 会拆掉它自己启动的东西，并且如实说明 —— 它不会去装防火墙规则，也从不声称会。

## 流量检查器

这个视图的第四个标签页是**流量检查器**：一个 Burp / Fiddler 式的代理，展示某台机器实际发出的 HTTP 与 HTTPS；终端与 SSH 会话会自动走它，而对证书做固定（pinning）的主机会被指名列出，而不是悄悄漏掉。

读取 HTTPS 意味着终止它，而终止它意味着持有一份本机信任的证书颁发机构 —— 这是 OpsMaxx 处理的密钥里最危险的一把，因为持有它的人可以向这台电脑冒充任何网站。首次运行时不会安装任何东西；信任该机构是一个需要管理员授权的明确动作，同时为 OpsMaxx 能写入的每个证书库都提供对应的移除操作，并且面板里会显示该证书的 SHA-256 指纹，供你确认本机信任的正是运行中的代理所用的那一个。监听地址若不是 `127.0.0.1`，会被直接拒绝而不是仅仅警告，因为那等同于向整个网络开放一个同时能解密 TLS 的代理。[SECURITY.md](../SECURITY.md#the-traffic-inspectors-certificate-authority) 说明了这把密钥如何生成、封存与约束。
