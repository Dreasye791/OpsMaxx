### OpsMaxx 是什么？

OpsMaxx 是一款免费、开源、跨平台的桌面应用，把 SSH 终端、SFTP 文件浏览器、SSH 隧道管理器、支持多种引擎的数据库客户端、加密的密钥保险库，以及一个供 AI 编程代理（Claude Code、Claude Desktop、Codex 等）安全接入的 MCP 桥，放进同一个窗口。它运行在 Windows、macOS 与 Linux 上，以 MIT 许可发布，且不需要账号。

### 我应该下载哪个文件？

Windows 上选 `OpsMaxx-x.y.z-setup.exe`，除非你特意要那个便携单文件版。macOS 上，M1 及更新的机器用 `-arm64.dmg`，Intel Mac 用 `-x64.dmg`。Linux 上，`.AppImage` 在任意发行版都能用；若你更想通过 `apt` 在 Debian 或 Ubuntu 上安装，那就选 `.deb`。发布页上的 `.blockmap` 与 `latest*.yml` 是构建元数据 —— 你永远不需要下载它们。

### OpsMaxx 真的免费吗？

是的。MIT 许可，个人与商业用途均免费，没有付费档、没有会话数上限、没有订阅。任何人都不应该向你收费。

### OpsMaxx 是好的 MobaXterm 替代品吗？

对大多数工作流来说，它是最接近的免费替代品，而且与 MobaXterm 不同，它同时支持 macOS 与 Linux。没有 12 个会话的上限，没有 Professional Edition，而内置的数据库客户端与保险库，覆盖了那些 MobaXterm 会把你打发去别处做的工作。MobaXterm 的 X11 服务器与它捆绑的 Cygwin 工具链在这里没有对应物。

### 它能替代 PuTTY 吗？

日常 SSH 可以 —— 有已保存会话、文件夹、标签页、可搜索的回滚缓冲，以及 PuTTY 风格的右键粘贴。它还能导入你 `~/.ssh/config` 里已有的服务器，因此不必重打。串口连接不支持。

### 它是开源的 Termius 替代品吗？

是。功能上的差别在于同步：Termius 在付费档通过它的云同步你的服务器。OpsMaxx 默认把一切留在本地，并用一个口令加密的备份文件在机器之间搬运。它自己只会发起一条连接 —— 更新检查，下面有说明。

如果你自建了一个中继，OpsMaxx 也能通过它在你的设备之间同步。那在你配置之前是关闭的，中继是**你自己运行**的服务器，而且它承载的一切在离开本机之前就已加密 —— 中继不持有密钥，读不到其中任何内容。但它仍然是一台你的数据会经过的机器，所以这一点值得说清楚，而不是让「不上传到任何地方」这句话把它盖过去。

### OpsMaxx 支持跳板机与堡垒机吗？

支持 —— 每台服务器可串联无限级跳转，就在服务器本身的同一个对话框里配置。每一跳既可以复用某个已保存服务器的凭据，也可以自定义自己的主机、端口、用户与密钥。`~/.ssh/config` 里的 `ProxyJump` 条目会自动作为跳板机导入。

### 支持哪些数据库？

PostgreSQL、MySQL、SQL Server、MongoDB 与 Redis —— 每种都有表/集合浏览器、查询编辑器与交互式 shell。它们都可以经 SSH 隧道访问，因此只能从内网路由的数据库同样能用。

### 能给我看 CI/CD 构建吗？

可以，但是只读。接上 Jenkins、GitLab 或 GitHub Actions 账号后，资产视图（<kbd>Ctrl</kbd>+<kbd>M</kbd>）里的 **CI/CD** 标签页会显示流水线、运行历史与失败步骤的日志，就放在这次运行改动的服务器旁边。这个标签页上的任何东西都不会启动、重跑或取消构建。

它在你于 *设置 → 模块* 中启用之前是**关闭的**，而原因不是其他只读模块给的那个。其他模块读的是你管理的机器，走的是你已经打开的连接；而这一个会用你交出的长期令牌定时轮询第三方的 API，且无论标签页是否在屏幕上都会持续轮询。构建输出也是本应用里第一类由**开合并请求的人**写成、而非由你拥有的主机写成的文本，因此无论它在哪里显示或交给代理，都被当作不受信任的内容对待。

### 我的密码和 SSH 密钥是怎么存的？

存在操作系统自己的凭据存储里，经 Electron `safeStorage` —— Windows 上是 DPAPI，macOS 上是 Keychain，Linux 上是 libsecret。没有任何东西以明文写入。保险库与加密备份在此基础上再加 AES-256-GCM 与 scrypt 密钥派生。

### OpsMaxx 会把数据发到什么地方吗？

没有账号、没有遥测、没有分析。关于你、你的资产或你如何使用这个应用的信息，都不会被采集或发送到任何地方。

有一条你没有配置过的连接：OpsMaxx 会在启动时检查新版本，之后每六小时检查一次，并下载它发现的版本。这项默认开启。它会从本项目的 GitHub releases 获取发布元数据 —— 因此 GitHub 会看到任何 HTTP 请求都会暴露的东西：你的 IP 地址与应用的用户代理 —— 而该请求不携带任何标识符，也不携带你资产里的任何内容。可以在
**设置 → 通用 → 自动更新** 中用「自动检查更新」关掉它；此后 **检查更新** 按钮就成了唯一会向外发起的动作。

除此之外的每一条连接，都是你自己配置的。

### 「复制诊断信息」里有什么？

关于这份安装本身的事实：应用版本与更新通道、这是打包版还是便携版、这个平台及其 Electron / Chrome / Node 版本、操作系统提供了哪个密码存储、有多少工作区、服务器、数据库、隧道与 VPN 配置、哪些可选模块是开着的，以及每个可配置功能是否既已开启又确实完成了配置。全都是计数、版本字符串与开关状态 —— 不含你资产里的任何名称。没有主机名、地址、用户名、文件路径或凭据，也不从任何服务器读取任何内容：这是它采集内容的**形态**，而不是事后加的一道过滤。

在崩溃界面上，它还会带上该次崩溃的消息与调用栈，而这两类东西性质不同 —— 它们是应用自己没有写过的文本，因此是被**过滤**、而非被塑形的。机密会被剥离，每条路径都会截到只剩最后一段，但一条「连不上某台主机」的报错通常会点名那台主机，而没有任何模式能可靠地区分主机名与普通单词。所以崩溃界面会在复制任何东西之前把整份报告展示给你：先读一遍，粘贴之后，把你不愿公开的行删掉。**复制诊断信息**本身不往磁盘写任何东西 —— 这个按钮只是把文本放进剪贴板，往哪儿去由你决定。左侧栏的 bug 按钮确实会保存文件，而且在保存前会先告诉你；见下文。

### 什么是调试模式？

它是对应用行为的录制，在你要求之前是关闭的。它之所以存在，是因为上一段里的一切描述的是你的安装**是什么** —— 版本、计数、哪些功能开着 —— 而对**它做了什么**一无所知；当某件事失败、行为异常或卡住时，恰恰是后者那一半要紧。

这一切都发生在**左侧栏的 bug 图标**上，无论你打开的是什么，它都在屏幕上。点它，选 **Start recording**（开始录制），它就关闭并把界面留给你 —— 录制期间图标上会一直带一个圆点。让问题再发生一次，然后第二次点这个图标。录制停止，它把录制内容与上一段那些信息合成一份报告，把整份展示给你，并在你按下保存后写成一个文本文件、同时打开 issue 表单且已填好你的版本与操作系统。把那个文件拖进 issue 里即可。

录制期间重启 OpsMaxx 没问题；录制会保留，而开始新的一次会清掉旧的。

**里面有什么。** 运行了哪些内部操作、各自耗时多久、哪些失败了，以及应用抛出的任何错误。永远不含这些操作的**参数**，因此密码、口令与密钥内容在构造上就不在其中，而不是靠过滤滤掉。形似机密的字符串 —— 令牌、密钥、`PASSWORD=` 赋值 —— 在写入任何东西之前就会被剥离。

**没有被过滤掉的内容。** 主机名、IP 地址、用户名、文件路径与命令文本。一条「连不上某台机器」的报错通常会点名那台机器，而没有规则能可靠地区分主机名与普通单词。这正是应用在写出报告之前把整份内容放到屏幕上的原因：读一遍，把你不愿公开的行删掉。

**它放在哪。** 应用自己的数据目录里的一个文件，只有你的用户账号可读，上限 8 MB。不会发往任何地方 —— OpsMaxx 从不上传它，报告由你自己附上，不附也可以。设置 → 高级 里会显示它的大小，并有一个 **删除** 按钮；提交缺陷报告不会删除它。

### 它能离线使用吗？

可以，完全离线。除了你连接的那些服务器，这个应用没有其他在线依赖。

### 支持双因素认证吗？

支持。它能应答 keyboard-interactive 挑战，并且连接会在会话、文件浏览与监控之间共享 —— 因此验证码只需输入一次，而不是每个标签页一次。

### 为什么 Windows SmartScreen 会警告它？

因为 Windows 构建没有代码签名证书。一张证书每年大约 200–400 美元，而这个免费、MIT 许可、没有收入的项目没有这笔钱。该警告意味着 Windows 无法确认**是谁**发布了这个应用，而不是说文件不安全 —— 如何绕过它以及扫描结果见[安装](install.md)。

**macOS 已经不再警告。** 自 0.30.1 起，macOS 构建已用 Apple Developer ID 签名并通过 Apple 公证，票据被装订进应用内，因此即使离线也能正常打开。`spctl -a -vvv /Applications/OpsMaxx.app` 会报告 `source=Notarized Developer ID`。

### 系统要求是什么？

Windows 10 或更新；macOS 11 或更新（Apple Silicon 与 Intel）；或现代的 64 位 Linux 发行版。从源码构建需要 Node.js 20 或更新。

### 我能把 Claude Code、Claude Desktop 或其他 AI 代理接到 OpsMaxx 上吗？

能 —— 见 [AI 代理接入](ai-agents.md)。OpsMaxx 运行一个本地 [MCP](https://modelcontextprotocol.io) 服务器，Claude Code、Claude Desktop、Codex、Gemini CLI 等兼容 MCP 的客户端都能连上，每个会话被限定在为其选定的工作区与权限配置之内。代理永远看不到密码、私钥、数据库凭据或保险库机密 —— 它只会拿到一个友好的服务器名，以及该会话配置所允许的范围。

### 让 AI 代理在我的服务器上跑命令安全吗？

它取决于你给它的配置有多安全，而这是一个真实存在的局限，不是一句口号 —— 这套设计保护什么、不保护什么，见 [docs/AI-SECURITY.md](AI-SECURITY.md)。OpsMaxx 确实提供了这些：桥只监听 `127.0.0.1`；每一项能力（执行命令、读写文件、SFTP、隧道、数据库访问、sudo、指标）都可独立设为 ALLOW/ASK/DENY；除 Bypass 之外的任何配置都拒绝不受限的 root shell（`sudo -i`、`su` …）；任何需要询问的动作都会停下，等你在 OpsMaxx 里批准或拒绝 —— 代理永远无法批准它自己的请求。每个会话的配置只有你能设：只读、先询问、自动、Bypass permissions（不经询问执行一切，包括 root shell），或自定义（套用你挑选的某个访问组）。把某台服务器标记为**已保护**后，任何配置都不能在它上面不经询问地做出改动。每个动作都会记入[审计日志](AI-SECURITY.md)，机密已脱敏，并且会标明哪些动作只是因为 Bypass 才得以运行。

### 我怎么把整套配置搬到另一台机器？

设置 → 备份与恢复 会写出单个口令加密的文件，包含工作区、服务器、数据库、隧道、凭据、保险库与受信任的主机密钥。在新机器上用同一个口令恢复即可。
